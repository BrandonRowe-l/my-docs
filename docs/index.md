## 项目简介

本次实践的目标是走通一条完整的静态文档发布链路：在本地用 Markdown 编写内容，通过 MkDocs Material 渲染成静态网站，再借助 GitHub Actions 在每次推送到 `main` 分支时自动完成安装依赖、构建和部署，最终由 GitHub Pages 对外提供访问。

## 实践体会

在动手之前，我对"文档网站"的理解还停留在手写 HTML 的阶段。完成这次实践后，我体会到 Markdown + 静态站点生成器的分工方式：内容与样式分离，写作者只关心 `docs/` 里的 Markdown 文件，构建产物 `site/` 完全由工具生成，不需要手工维护。自动部署带来的收益也很直观——文档修改后只需要一次 `git push`，剩下的构建、上传、发布全部由流水线完成，避免了手工部署时容易出现的遗漏和版本不一致问题。
